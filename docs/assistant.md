## Реализованная рабочая цепочка

1. Посетитель открывает кнопку «Подобрать с ИИ». Окно само не раскрывается, есть быстрые стартовые вопросы.
2. Сервер проверяет размер и схему запроса, источник, включённость помощника и квоты.
3. Активная модель уточняет потребности и возвращает структурированные фильтры и краткую сводку. Максимум два вопроса за ход. Системная инструкция — `src/lib/assistant/provider.ts`.
4. Сервер ищет только **published** объекты через `findPublished`, с правами анонимного посетителя. Максимум четыре карточки за запрос, без загрузки всего каталога. Цена, заголовок, фото и URL приходят из БД, модель не формирует карточки.
5. Фильтры первой версии: покупка/аренда, Алания, район, тип, планировка, бюджет/валюта, расстояние до моря, мебель. Неизвестный район или город не заменяются молча Аланией. Бюджет без валюты требует уточнения; конвертация по курсам админки. Цена аренды — за месяц. Объекты без цены не проходят ограничение бюджета.
6. Посетитель отмечает до четырёх вариантов. Форма показывает сводку; имя, WhatsApp и согласие обязательны. В `leads` сохраняются сводка, ID, история разговора, язык, UTM и страница. Выбранные объекты повторно проверяются на опубликованность.
7. Назначение заявки: существующая логика по первому доступному выбранному объекту; без объекта — первый видимый эксперт. Если экспертов нет, заявка остаётся неназначенной для обработки администратором. Письмо использует существующий SMTP-механизм; успех формы означает сохранение заявки, а не гарантию доставки письма.

Контакты из формы не передаются модели. Сам посетитель может написать личные данные в чате: интерфейс предупреждает об обработке сообщений ИИ-сервисом. История живёт только в памяти страницы и записывается в заявку после согласия. Это не постоянный архив всех чатов. Необработанные ответы провайдеров, ключи и переписка в логи новых обработчиков не выводятся.

## GPT и Claude

В `Настройки → ИИ-консультант` только администратору доступны:

- включение/выключение;
- активный провайдер OpenAI или Anthropic;
- API ID модели каждого провайдера;
- два независимых ключа и проверка доступа к выбранной модели;
- общий суточный лимит запросов, по умолчанию 100 (UTC).

OpenAI: Responses API, исходная модель `gpt-6-astra`, `reasoning.effort=low`, `store=false`. Anthropic: Messages API, исходная модель `claude-sonnet-5-5`. Обе интеграции используют Structured Outputs и повторную проверку Zod на сервере. Один вызов модели на сообщение, максимум 2200 выходных токенов и 45 секунд ожидания. Поддержку другой модели нужно проверить до переключения; автоматического перехода на другого провайдера при ошибке нет.

Проверка ключа запрашивает доступ к модели через Models API, без генерации текста. **Это не проверка качества и успешности полноценного ответа.** При неудачной проверке старый ключ остаётся. Кнопка сохраняет ключ сразу; настройки модели/провайдера нужно сохранить штатной кнопкой страницы.

Ключи шифруются AES-256-GCM с отдельным `AI_CREDENTIALS_SECRET` (32 случайных байта в base64). В REST/GraphQL ciphertext скрыт field access, даже от администратора. Повторно ключ не показывается. Шифровальный секрет хранится в окружении сервера, не в БД и не в git. При смене секрета старые ключи требуется ввести заново. Владелец сайта вводит ключ в админке; присылать его в чат не нужно.

Квоты хранятся в PostgreSQL (`assistant_limits`): атомарное увеличение, общий суточный потолок и 20 сообщений с IP за 10 минут. Заявки и проверки ключа — по 5 за 10 минут. IP хранится как HMAC, старые счётчики удаляются. Это ограничения количества, **не денежный бюджет**; перед запуском нужны лимиты расходов аккаунта провайдера и проверка доверенного IP-заголовка хостинга. Для Vercel используется `x-vercel-forwarded-for`; для другого прокси следует настроить доверенный источник адреса.

Роли переиспользованы: `admin`, `editor`, `agent`. Новые настройки закрыты для редактора и агента серверными проверками. Агент видит назначенные ему заявки через существующий `ownByAgent`. Существующие права редактора на все заявки в этой ветке не изменялись.

## Установка на тестовую БД

1. Настроить **локальную/тестовую** PostgreSQL, `DATABASE_URL`, `PAYLOAD_SECRET` и `AI_CREDENTIALS_SECRET` по `.env.example`.
2. `npm run migrate` — добавочная миграция `20261019_124840_assistant_settings`. Изменяет только новые таблицы настроек/квот и поле истории в `leads`; старые миграции не переписаны. Откат удаляет историю и новые настройки — только на одноразовой тестовой БД или после резервной копии.
3. `npm run generate:types`, `npm run generate:importmap` уже выполнены, результаты входят в ветку.
4. Войти администратором, сохранить выбранные настройки модели, ввести соответствующий ключ, проверить и включить помощника. По умолчанию он выключен.
5. Пройти рабочий диалог на `/ru`, `/en`, `/tr`, отправить тестовую заявку с согласием, проверить запись и назначение в админке.

## Границы первой версии и следующие этапы

Это первый локальный вариант, не готовый боевой релиз. Он знает каталог через фильтры, названия районов и основные контакты/часы работы агентства. Полнотекстовые ответы по всем статьям, услугам и страницам, сравнение найденных карточек, карта и сохранение диалога между посещениями пока не реализованы. Модель не получает результаты поиска для дополнительного рассуждения. Нестандартные требования передаются менеджеру, без обещания, что найденные карточки им соответствуют.

Следующий этап: тестовая БД и ключ → сценарные проверки обеих моделей → источники знаний по опубликованным услугам/статьям с цитатами → оценка стоимости и конверсии → решение владельца о переносе. До включения на рабочем сайте нужно дополнить политику обработкой чата выбранным ИИ-провайдером и определить сроки хранения переданных диалогов. Автоновости не включены в эту задачу.

Официальные схемы сверены с [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Anthropic Structured Outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [моделями Claude](https://platform.claude.com/docs/en/models/overview). Проверка доступности конкретной модели в аккаунте остаётся обязательной.
